# GameKit 项目画像与方向

## 项目概述

GameKit 是给孩子用的 AI 辅助 pygame 游戏工作室。可以把它理解成「写 Python 的 MakeCode Arcade」：
想点子、写代码、试玩、改错、做素材、导出成品，都在一个浏览器页面里完成；
不同的是孩子写的不是积木，而是真正的 Python + pygame-ce 代码，导出后在自己电脑上的 Python 里也能运行。

服务对象是已经会一点 Python、想做自己第一个游戏的孩子（约 10～15 岁），以及陪他们做的家长和老师。

运行方式：

- 游戏在孩子自己的浏览器里运行（pygbag：pygame-ce + CPython 3.12 WebAssembly，见 [runtime.md](runtime.md)）。
- 页面是本地优先的 PWA：不登录也能新建、编辑、运行、导出，作品存在本机。
- 授权用户用 Cloudflare 单点登录（GitHub 身份）登录后，额外获得 AI 生成和云端同步。
- 页面通过 WebMCP 把工作室的操作暴露给浏览器里的 AI Agent，让外部助手也能按同样的规则帮忙。

## 项目画像（目标状态）

- **真 pygame。** 孩子写的是标准 pygame-ce。没有隐藏的 GameKit 游戏 API，构建不偷偷改写源码；
  教程和配方需要的辅助代码，以普通 `.py` 文件的形式放进项目，孩子看得见、改得动，桌面 Python 也能跑。
- **打开就能做游戏。** 首页三步内能跑起一个会动的游戏：选配方或说出点子 → 点「运行」→ 在舞台上玩。
  不登录、不安装、不配置。
- **孩子看得懂、敢动手。** 中文优先，大按钮、少面板、短句子；新手布局只露出最常用的东西，
  进阶布局才出现完整文件树和调试面板。报错先给孩子能懂的中文解释和下一步，再给 Python 原文。
  任何改动都能撤销，所以乱试不会闯祸。
- **AI 是教练，不是代笔。** AI 覆盖做游戏的全过程：出点子、拆步骤、写代码、做素材、看报错、讲解、出挑战。
  但每一次改动都小、看得见、要孩子点头、能撤销，并附带「改了什么、为什么」。孩子始终是作者。
  完整规则见 [ai-rules.md](ai-rules.md)。
- **登录是门禁，不是门槛。** 只有授权名单里的用户能登录；登录只解锁 AI 和同步，
  不登录的孩子照样能完整地做游戏。
- **安全默认。** 密钥永远不进浏览器；身份或配置有任何不确定，一律拒绝；只收集运行所需的最少信息。
- **一套工具，多个入口。** 界面按钮、内置 AI、WebMCP 外部 Agent 操作项目时走同一套工具和同一套确认规则，
  不会因为入口不同而绕过规则。
- **可验证。** 核心路径由端到端测试守护；AI 的输出规则、权限边界有自动化测试证明。

品质冲突时的优先级：
**孩子的作品不丢 > 安全与授权 > 与真 pygame 一致 > 孩子看得懂 > AI 能力 > 功能数量。**
例如：宁可让 AI 少做一步、多让孩子确认一次，也不能静默改动项目；
宁可让某个写法在浏览器里给出明确提示，也不能为了「能跑」偷偷改写孩子的代码。

这些是项目或用户已经定下的选择。改动它们属于改边界，需要先确认。

| 托管 | 一个 Cloudflare Worker + 静态资源，域名 `gamekit.talkincode.net`，CI 通过后自动部署 | `wrangler.jsonc`、`.github/workflows/ci.yml` |

## 当前能力清单

以下是当前代码中已经存在的能力。界面主体仍是英文、面向开发者的 IDE 布局，还没有儿童化；新增的登录与 AI 提示是中文（`src/ui/text.ts`）。

- 多文件项目与本地保存

项目存在浏览器 IndexedDB（库 `gamekit`，表 `projects`）。新建示例或空白项目、打开、改名、复制、删除，
新增/删除/改名文件，导入二进制素材，导入源码 zip。入口 `src/studio/store.tsx`、`src/lib/storage.ts`、`src/lib/project.ts`。

- 起始示例

一个带精灵图和跳跃音效的可玩示例（`src/lib/starter.ts`、`src/lib/samples/`）。

- 代码编辑

Monaco 编辑器，Python 高亮，选区可交给 AI（`src/ui/CodePane.tsx`）。

- 浏览器内运行

用 pygbag 模板打包当前项目，页面 Service Worker 把本次构建放进 Cache，iframe 打开 `/play/<id>/` 运行；
Stop 结束会话。入口 `src/lib/build.ts`、`src/lib/session.ts`、`public/sw.js`、`runtime/player.tmpl`、`src/ui/PreviewPane.tsx`。

- 诊断

静态检查帧循环是否 `await asyncio.sleep(0)`、阻塞式 sleep、非 OGG 音频；从控制台 traceback 定位出错行；
调试页显示运行状态、FPS、帧时间和输入事件。入口 `src/lib/diagnostics.ts`、`src/ui/BottomPanel.tsx`。

- 登录与授权

工具栏「登录/退出」是整页跳转到 `/api/login`、`/api/logout`。生产环境由 Cloudflare Access（GitHub）登录，
Worker 对每个 `/api/*` 请求校验 Access JWT（签名、aud、iss、过期）并核对 `ALLOW_GITHUB_USERS`；配置缺失时拒绝。
页面只在本机登录过时才询问 `/api/me`，匿名访问不发任何身份请求。本地开发用 `LOCAL_DEV_AUTH=1` 的替身登录表单，
只在 localhost 生效。入口 `worker/identity.ts`、`worker/index.ts`、`src/lib/account.ts`、`src/ui/Toolbar.tsx`。
**线上状态：** Access 应用已创建、`ACCESS_AUD` 已写入、secret 已写入；新代码随 `main` 部署后生效。

- AI 代码助手（仅授权用户）

六种操作：从点子初始化项目、生成文件、补全、重构、讲解、修错。模型结果先显示 diff，接受后才写入，可撤销；
只允许改文本文件，拒绝越界路径和替换二进制素材。文本模型是服务端的 OpenAI 兼容接口；系统提示词要求中文讲解、
孩子读得懂的代码和儿童适宜内容。入口 `src/lib/ai.ts`、`src/studio/store.tsx`、`src/ui/Overlays.tsx`、`worker/ai.ts`。

- AI 素材生成（仅授权用户）

精灵、背景、瓦片、图标四种提示模板，Workers AI 生图，服务端追加儿童安全约束，预览后接受才存入 `assets/`。

- 导出

网页 zip、静态目录 zip、itch.io zip、嵌入 zip、源码 zip；导出包不依赖 GameKit 站点。入口 `src/lib/export.ts`。

- 部署

推送 `main` 后 CI 单元测试、类型检查、构建、E2E，全部通过后 `wrangler deploy`（`.github/workflows/ci.yml`）。

尚不存在：云同步、PWA 清单与离线外壳、WebMCP、完整的中文与儿童化界面、教程与配方、
精灵/瓦片/音效编辑器、AI 按人配额。

## 非目标（铁律）

- **不做积木编辑器。** 不做 Blockly 式拖拽，也不做「积木转 Python」。GameKit 的价值就是让孩子直接写 Python。
- **不发明私有游戏 API，不改写 pygame。** 需要的辅助代码必须是项目里可见的 `.py` 文件，并能在桌面 pygame-ce 上运行。
  构建过程不改写孩子的源码。
- **不在服务器上运行孩子的代码。** 游戏只在浏览器里运行；服务器只做身份、AI 转发和数据存取。
- **浏览器里不出现任何 AI 密钥，不做「自带 API Key」。** AI 只经由 Worker 调用，只对授权用户开放；
  前端不能选择模型供应商或接口地址。
- **不做开放注册，不自建账号密码。** 身份只来自 Cloudflare Access（GitHub）；授权名单之外的人无法登录，
  也没有「登录了但降级使用」的中间状态。
- **生产环境没有任何绕过登录的开关。** 本地开发如需模拟身份，只能在本地运行时生效；
  这类配置出现在生产部署里应当导致请求被拒绝，而不是放行。
- **登录不是使用前提。** 未登录时，新建、编辑、运行、导入、导出都必须完整可用，且不发起需要身份的网络请求。
- **任何入口都不能静默改项目。** 内置 AI、WebMCP 外部 Agent、同步、导入，凡是会改变孩子作品的操作，
  都要么新建项目，要么先展示改动、由人确认，并且可撤销。
- **同步不静默覆盖。** 两台设备改了同一个项目时保留两份，让人选择；不做「最后写入者赢」。
- **不做公开作品广场和社交功能。** 不做公开发布、评论、点赞、私信；它们带来的儿童内容审核和隐私责任超出本项目边界。
  分享只通过导出文件完成。
- **不接入第三方统计、广告或追踪 SDK。** 服务端日志只记录诊断所需的元数据，不记录孩子的代码和提示词全文。
- **不托管成品游戏，不对接第三方发布平台账号。** 导出只生成文件（沿用现有边界）。

## 方向与意图

- 儿童友好的工作室界面

中文优先（文案集中管理，便于以后加其他语言），大号可点目标、清晰的图标与颜色、适配平板触控和键盘。
新手布局只保留「配方/点子 · 代码 · 舞台 · 小助手」；进阶布局展开文件树、问题列表和调试面板。
报错、空状态、加载、失败都用鼓励式短句，技术细节折叠在「给大人看」里。服务于「孩子看得懂、敢动手」。

- 游戏配方与分步教程

对标 MakeCode Arcade 的教程体验：平台跳跃、打飞机、迷宫、贪吃蛇、接球等配方，每个都是完整可玩的 pygame 项目；
分步教程每步只改一处、运行后自动检查是否做到。加载配方或教程总是新建项目。服务于「打开就能做游戏」和「真 pygame」。

- 内置创作工具

像素精灵编辑器（含动画帧）、瓦片地图编辑器、音效合成器（本地参数化生成 OGG）。产物是普通的
PNG/OGG/数据文件，代码用标准 pygame 读取。不依赖 AI，未登录也可用。服务于「打开就能做游戏」。

- AI 小助手覆盖全流程

从一次性的「六个按钮」升级为一个对话式小助手：帮孩子把点子变成游戏设计卡、拆成小步骤、逐步生成与修改、
读运行时的报错和控制台去修 bug、讲解任意一行、给出下一步挑战、生成风格一致的素材。
助手看到的上下文（相关文件、诊断、控制台、舞台截图）由工具层提供，改动一律走提议 → 预览 → 确认 → 可撤销。
行为规则只在 [ai-rules.md](ai-rules.md) 维护。服务于「AI 是教练，不是代笔」。

- 登录与授权

已实现（见「当前能力清单」）。还想要的：Access 拦截页改成孩子看得懂的文案；登录过期时不打断正在进行的编辑。
服务于「登录是门禁，不是门槛」和「安全默认」。

- 云端同步

登录后项目在设备之间同步。本地仍是第一份数据：离线照常编辑，联网后再同步。
首次登录时询问是否把本机未登录时的作品带进账号；退出登录时可选择清除本机上属于该账号的数据（照顾共用电脑）。
冲突保留两份。服务于「孩子的作品不丢」。

- PWA 与离线

可安装、可离线打开和编辑；运行游戏所需的 pygbag 运行时在首次使用后缓存，断网也能运行已缓存版本。
更新时提示刷新，而不是在孩子编辑时突然换版本。服务于「打开就能做游戏」。

- WebMCP

把工作室工具层注册为 WebMCP 工具，例如：列出和读取文件、读取诊断和控制台、运行/停止游戏、
提议修改（进入同一个确认界面）、新建项目。只读和运行类工具未登录可用；
会消耗 GameKit AI 的工具要求登录；任何写入仍需页面上的人确认。工具定义与内置小助手共用一份。
服务于「一套工具，多个入口」。

- 看得见的调试

补齐 [runtime.md](runtime.md) 里「还没做」的部分：碰撞盒、精灵边界、鼠标坐标叠加、音频通道状态，
以及把常见 pygame/Python 报错翻译成孩子能懂的中文。服务于「孩子看得懂」。

## 完成的样子

> 当一个没用过 GameKit 的孩子能在几分钟内跑起一个会动的游戏、在小助手帮助下把它改成自己的样子、
> 导出后在家里电脑的 Python 里照样能玩，而家长能确信只有授权的人能用 AI、作品不会丢时，这个项目就达成了。

- 孩子的核心路径由端到端测试守护

打开 → 选配方 → 运行 → 改代码 → 再运行 → 导出，在生产构建上有自动化测试；回归会在 CI 中被挡下。

- 权限边界由测试证明

匿名、授权用户、已通过 Access 但不在名单内三种身份，对每个需要身份的接口都有测试证明结果正确；
配置缺失时接口拒绝服务。

- AI 规则可验证

模型输出的解析与拒绝规则（路径、文件类型、二进制素材、大小）有单元测试；
改动 AI 提示词或上下文时，有一组固定的样例请求用来比较改动前后的结果。

- 数据不丢可验证

本地保存、刷新后恢复、同步冲突保留两份、同步失败后本地不受影响，都有测试。

- 离线可用可验证

断网状态下能打开页面、打开项目、运行已缓存运行时的游戏。

## 验收矩阵（业务能力覆盖矩阵）

> 覆盖底线（硬性规定）：
>
> 1. 每个一级功能至少有一条 Happy Path E2E。
> 2. 每个高风险功能至少覆盖一条失败路径。
> 3. 每个涉及权限的功能至少验证两种角色。
> 4. 每个会修改系统状态的操作至少验证一次失败后的恢复或回滚。
> 5. 每次新增一级业务功能，必须同步新增对应的 E2E 并更新本矩阵。

权限角色：**匿名**、**授权用户**、**已登录未授权**（通过了 Access 但不在 Worker 授权名单内，或 JWT 无效）。

| 一级功能 | 状态 | 风险级别 | Happy Path E2E | 失败路径 | 权限角色覆盖 | 失败恢复/回滚 | 证据（测试路径/用例） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 本地项目管理 | 已有 | 高（作品丢失） | ❌ 缺口 | ❌ 缺口 | 不适用 | ❌ 缺口 | 单元：`src/lib/project.test.ts`（`rejects traversal and keeps stable names`） |
| 代码编辑 | 已有 | 低 | ❌ 缺口 | 不适用 | 不适用 | 不适用（持久化见上一行） | 无 |
| 浏览器内运行 | 已有 | 中 | ❌ 缺口 | ❌ 缺口 | 不适用 | 不适用（不改持久状态） | 单元：`src/lib/export.test.ts`（打包与模板） |

缺口的最低期望：

- **E2E 基础设施：** 已搭好（Playwright，`tests/e2e/`，生产构建 + `vite preview`，替身模型 `tests/e2e/mock-model.mjs`）。
  下一步是打开页面、运行起始示例并看到游戏画面（需要 pygame-web CDN）。
- **本地项目管理：** 编辑后刷新仍在；删除需要确认；IndexedDB 写失败时界面提示且内存中的内容不丢。
- **浏览器内运行：** 运行起始示例、Stop、再次运行；运行一个有语法错误的项目时出错行被定位。
- **AI 素材：** 补一条用替身生图的 E2E（生成 → 预览 → 接受后出现在 `assets/`）。
- **登录与授权：** 上线后用真实 GitHub 账号走一遍登录、被拒、退出；Access 会话过期后的表现要与 E2E 一致。
- **云端同步：** 两台设备冲突保留两份；网络中断后本地不受影响、恢复后能续传；一个用户读不到另一个用户的项目。
- **WebMCP：** 未登录时只读工具可用、AI 类工具被拒绝；写入类工具在人确认前不改项目，拒绝后项目不变。
- **部署回滚：** 写明出问题时如何回到上一个版本（例如 `wrangler rollback`）并演练一次。

「不适用」的理由已写在单元格里：只读功能不改持久状态；导入、配方、教程总是新建项目，不覆盖已有作品。
